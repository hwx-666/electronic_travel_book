# 阶段 5 交付说明：账号体系 + 图文回忆上云

> 交付时间：2026-11-21 ｜ 对应 README 版本 v0.3.0 ｜ 前置阶段 4.1（已交付并确认）

## 一、本阶段交付了什么

在阶段 4（中国/外国两级下钻 + 旅行回忆 + 点亮推导）基础上，接入 Supabase 云端后端：

1. **邮箱 + 密码账号体系**
   - 注册 / 登录 / 登出；默认开启邮件确认（注册后需查收确认邮件再登录）；
   - 刷新不掉登录态（AuthProvider 挂载时恢复会话 + 订阅 onAuthStateChange 多端同步）；
   - 未登录时整站唯一可见页为登录/注册（AppGate 全局门控），右上角全局登出条；
   - 数据按用户隔离（RLS），换账号自动清空本地数据。
2. **图文回忆上云（数据库 + Storage）**
   - 回忆文本存 `memories` 表，照片存 `photos` bucket；
   - 三种回忆形态：纯文字 / 纯图片 / 图文混合，单条最多 9 张；
   - 客户端压缩后再上传：展示图长边 ≤1280px、体积 ≤300KB（JPEG 质量迭代），
     缩略图长边 ≤200px；自动修正 EXIF 方向、透明底转白；
   - 写入顺序（insert 回忆 → 传图 → 批量插照片元数据）任一步失败回滚，表单输入不丢；
   - 删除回忆先删 Storage 文件（尽力）再删记录（照片行 cascade 连带清除）；
   - 大图查看（左右切换）。
3. **本地 v2 回忆一键导入**
   - 登录后回忆区出现「导入本地回忆」按钮，把旧版 localStorage 回忆幂等导入云端
     （按 id 判重，失败可重试不重复），成功后清空本地。
4. **RLS 收紧**
   - `memories` / `memory_photos` 只允许 `auth.uid()` 访问自己的行；
   - Storage 对象策略：公开读 + 仅登录用户可写 `photos/<自己的user_id>/…` 路径
     （防跨用户目录覆盖/越权删）。
5. **工程质量**
   - `npm run lint`（oxlint）零警告通过；
   - `npm run build`（tsc + vite）通过；
   - `npm run verify:data`（本地 6 国 + 远程抽样）全 PASS，阶段 4 数据无回归。

## 二、验收清单

### 本地验收（开发机）

```bash
npm install          # 安装 @supabase/supabase-js
npm run lint && npm run build && npm run verify:data   # 三连：均需通过
npm run dev          # http://localhost:5173
```

浏览器实测流程（需要 .env 已配置且表/桶已就绪，见下文"部署前你要执行"）：

- [ ] 打开首页被重定向到登录/注册页，注册一个账号 → 提示"查收确认邮件"
- [ ] 邮件确认后登录 → 进入 3D 地球
- [ ] 进入某国家/地区页，添加一条带照片的回忆 → 缩略图显示、卡片出现
- [ ] 点击缩略图 → 大图查看，可左右切换、关闭
- [ ] 再添加一条纯文字回忆 → 三态卡片并存
- [ ] 删除回忆 → 二次确认后消失，照片一并清除
- [ ] 刷新页面 → 登录态保持、回忆还在（云端读回）
- [ ] 若本机有旧版回忆 → 回忆区出现「导入本地回忆」→ 点击导入成功且不重复
- [ ] 登出 → 回到登录页；换另一个账号登录 → 看不到上一个账号的回忆
- [ ] 两个浏览器/设备同时登录 → 数据按账号一致（云端共享）

### 线上验收（部署后）

- [ ] 线上站点能注册/登录/登出，功能与本地一致
- [ ] 添加图文回忆后刷新不丢
- [ ] 中国地图、外国地图两级下钻仍正常（阶段 4 回归）

## 三、部署前你要执行（仅一次，10 分钟）

代码已全部就绪并通过本地三连，**数据库侧还差两步配置，需要你在 Supabase
Dashboard 操作**（我只能读，anon key 无权建桶/改策略）：

### 第 1 步：执行建表 + 建桶 + 收紧 SQL

打开 Supabase Dashboard → 你的项目 → **SQL Editor**，整段粘贴执行
`scripts/supabase-schema.sql`（幂等，可重复跑）。它包含：

1. 幂等建表 `memories` / `memory_photos`（若已存在跳过）；
2. 创建 `photos` bucket（public，若已存在跳过）；
3. **RLS 收紧**：先 drop 掉放行版旧策略（如果有），再建按 `auth.uid()` 隔离的策略；
4. Storage 对象策略（公开读 + 按路径首段鉴权的写/改/删）。

> 文件末尾附「回退 SQL」注释块：如需退回放行版策略，照注释执行即可。

### 第 2 步：检查 Auth 配置

Dashboard → Authentication → Providers → Email：

- Email 确认：**开启**（默认，符合需求文档"保留邮件确认"）；
- 密码最小长度：≥ 6（默认 8 位即可，前端按 6 位校验）。

### 第 3 步（可选）：确认环境变量已注入 CI

部署工作流 `.github/workflows/deploy-pages.yml` 会读取仓库 Secrets 里的
`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`。若之前没配过：

- GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret；
- 与本地 `.env` 保持一致。

## 四、设计取舍（请知悉）

| 取舍 | 说明 |
| --- | --- |
| 保留邮件确认 | 需求文档默认值；代价是注册后要先去邮箱点确认。如想免确认（demo 更快），改 Auth 设置关闭即可，前端无需改动 |
| 云端为真源 | 登录后全量拉取到内存，地图点亮零查询；数据量在免费层（500MB 文本）内无压力 |
| 照片免费层配额 | 1GB Storage，图片已压至 ≤300KB/张；建议习惯性控制照片总量，避免撞配额 |
| 无改密/找回密码 UI | 需求未要求；AuthPage 注明"联系管理员重置"。如需可后续加 |
| 展示图 + 缩略图双份 | 列表用缩略图（快），大图用展示图（清晰）；存储成本约 2× 但体验好 |
| 大包提示 | 构建产物 2.6MB（gzip 758KB），主要来自 three.js/globe.gl；功能不受影响，后续可按需分包 |

## 五、风险与遗留

- **照片删除是尽力而为**：若网络在"删 Storage 文件"与"删记录"之间中断，可能留孤儿
  文件（极小概率，不影响功能，仅占配额）。
- **Cloudflare 数据本地化**：2026-11 起 1.1.1.1 在国内不可达，地图远程数据改为
  CNAME + 环境变量区（vite 代理），阶段 3 已处理，本阶段无新增依赖。
- 下一步（未做，留待阶段 6）：改密/找回密码、回忆编辑、照片删除单个重选、
  云端配额监控。

## 六、回退方案

- 数据库：执行 `scripts/supabase-schema.sql` 文末注释块里的回退 SQL，可还原放行版
  策略（表结构本身幂等保留）。
- 前端：git 回滚到 `v0.2.1` 标签即回到阶段 4.1 纯本地版（localStorage）。
- 部署：GitHub Pages 分支模式，回滚 = 重新推送旧 tag 或手动回退 gh-pages 分支。
